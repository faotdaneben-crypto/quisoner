🎯 HOW TO RUN (QUICK START)
================================================================================

STEP 1: Navigate to project directory
```bash
cd C:\Users\Digitalisasi\quisoner\packages\surveys-app
```

STEP 2: Install dependencies (already done ✓)
```bash
npm install
```

STEP 3: Configure environment variables
Create `.env` file from `.env.example`:
```bash
cp .env.example .env
```

Edit .env with your database connection:
```
DATABASE_URL="postgresql://username:password@localhost:5432/surveys_db"
JWT_SECRET="your-super-secret-random-string"
```

STEP 4: Setup database (requires PostgreSQL running)
If using local PostgreSQL:
```bash
# Create database first
createdb surveys_db

# Run migrations
npx prisma db push

# Seed initial data (creates admin user)
npx prisma db seed
```

Or if using Supabase cloud database:
```bash
npx prisma db push
npx prisma db seed
```

STEP 5: Start development server
```bash
npm run dev
```

STEP 6: Access application
Open browser to http://localhost:3001

URLs:
- Patient Survey: http://localhost:3001/survey
- Admin Login: http://localhost:3001/admin/login

💡 KEY ARCHITECTURAL DECISIONS
================================================================================

Why Next.js instead of standalone backend?
- Server-side rendering for better SEO
- API routes eliminate separate backend layer
- Type safety with TypeScript throughout
- Easy deployment to Vercel/Node hosting

Why Prisma over raw SQL?
- Type-safe queries with generated types
- Automatic migrations
- Better security (parameterized queries)
- Faster development cycles

Why JWT authentication?
- Stateless (no session storage)
- Works well with mobile/hybrid apps
- Easy to integrate with third-party services
- Standard industry practice

Why responsive mobile-first design?
- Most patients will access via phone/tablet
- Touch-friendly large buttons
- Readable text without zoom
- Fast loading on slow networks
